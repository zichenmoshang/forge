# 现有代码索引方案

## 定位

现有代码索引是项目级的，针对当前正在开发的项目，用于：
- 理解现有代码结构和模式
- 复用已有组件/hooks/utils
- 代码修改场景下精确定位修改位置
- 保证生成代码与现有风格一致

与历史知识库的区别见 [知识库方案](04-knowledge-base.md)。

## 索引内容

### 1. 符号索引（最核心）

用 AST 解析所有源文件，提取符号定义：

| 符号类型 | 提取内容 | 用途 |
|---|---|---|
| 组件 | 组件名、文件位置、props 定义、事件 | 阶段3 检测可复用组件；阶段5 直接引用 |
| 函数/Hooks | 名称、位置、参数、返回类型、用途 | 复用已有逻辑 |
| 类型/接口 | 名称、字段定义 | 数据模型对齐，避免重复定义 |
| 常量/配置 | 名称、值 | 引用已有常量 |
| API 调用 | 接口路径、封装位置 | 复用已有请求封装 |

检索方式：精确匹配（按名称、按类型），不是语义模糊匹配。

### 2. 代码语义索引（辅助）

把代码按语法单元切分（函数级、组件级，不是按文本行数），向量化建立语义索引：
- "这个项目里有没有处理表单校验的工具"——不知道具体名称时的模糊查找
- "类似这个需求的现有实现在哪里"——找参考代码

语义索引是符号索引的补充。

### 3. 依赖关系图

构建文件之间的 import/export 关系图：
- 修改影响分析：改了这个文件，哪些地方受影响
- 新增模块定位：新代码应该放哪个目录、引用哪些已有模块
- 循环依赖检测：生成的代码是否引入循环依赖

### 4. 项目配置读取

直接读取配置文件：
- `package.json` → 技术栈、依赖版本、脚本命令
- `tsconfig.json` → TypeScript 配置、路径别名
- eslint 配置 → 代码规范
- 构建配置（vite/webpack）→ 构建方式、别名
- 目录结构 → 项目分层约定

## 处理时机

### 首次接入项目（一次性）

```
扫描仓库 → 排除 node_modules/dist 等
  → AST 解析源文件 → 建立符号索引
  → 代码切方向量 → 建立语义索引
  → 解析 import 关系 → 构建依赖图
  → 读取配置文件 → 提取技术栈和规范
```

### 代码变更时（增量）

- 监听 Git 变更，只重新解析变更的文件
- 更新符号索引、语义索引、依赖图
- 每次生成 PR 前自动同步一次

## 在流程中的使用点

| 阶段 | 用途 |
|---|---|
| 阶段3 方案设计 | 检索现有组件/hooks，标记"可复用"；检查目录结构，确定新模块位置 |
| 阶段5 TDD 编码 | 生成代码前检索相关现有代码作为上下文，保证风格一致；代码修改场景精确定位修改位置 |
| 阶段6 CR | 检查新增代码是否重复了已有实现；检查是否正确引用已有组件/类型 |
| 阶段7 PR 交付 | 修改影响分析，确认改动范围合理 |

## 关键原则

1. **项目级建设**：每个项目单独建索引，不跨项目混用
2. **符号索引为主**：精确匹配优先，语义检索为辅
3. **按语法单元切分**：代码向量化按函数/组件切，不按文本行数
4. **增量更新**：代码变更后自动同步，不重新全量扫描
5. **与知识库共用基础设施**：向量库、AST 解析共用，但数据分开存储
