# 项目概述

## 目标

构建一个自动化智能体，接收需求 PRD 文档，端到端完成从需求理解到高质量前端代码交付的全过程，最终以 PR 形式输出。

## 范围

### 包含

- 需求 PRD 解析与澄清
- 用户故事拆解与验收标准生成
- 前端技术方案设计
- TDD 驱动的前端代码生成
- AI 方案评审与代码 CR
- 以 PR 形式交付代码

### 不包含（v1）

- 后端代码生成
- 数据库变更
- 上线部署与线上监控
- 集成测试、回归测试、探索性测试（仅做 mock 级测试）
- 产品验收与 UAT

## 输入

| 输入 | 说明 | 提供时机 |
|---|---|---|
| PRD 文档 | 需求文档，支持 Word/PDF/Markdown/飞书文档 | 流程开始 |
| Figma 设计稿 | UI 设计，通过 Figma API 提取设计数据 | 方案设计阶段前 |
| 埋点需求 | 随 PRD 一起提供 | 流程开始 |
| 全局需求 | 登录体系、权限等全局需求，单独提供 | 流程开始或澄清阶段补充 |

## 输出

- 结构化需求文档
- 用户故事列表（含验收标准）
- 前端技术方案设计文档
- 前端代码（含测试）
- 测试报告
- CR 记录
- PR（含自动生成的 PR 描述）

## 关键约束

1. **产物依赖前向**：后续阶段产物建立在前面阶段基础上，前面错了后面大概率也错
2. **验证与修正双向**：每个阶段有进入下阶段的质量门，同时下游发现问题可回退上游修正
3. **弱模式人工介入**：AI 自动推进为主，人工可在任意节点介入；3 个硬卡点必须人工
4. **设计稿外部依赖**：Figma 作为外部输入，方案设计阶段消费
5. **API 契约人工确认**：方案先经 AI 评审，评审通过后的 API 契约再由人工确认（ADR-014：确认的是稳定版，避免评审改动导致重复确认）
6. **测试仅到 mock 级**：基于确定的数据协议 mock 接口数据，保证代码基本逻辑

## 硬人工卡点（不可去掉）

1. 需求澄清问答
2. API 契约确认
3. 最终交付确认

## 交付场景

- 新项目：初始化项目结构 + 配置 + 生成代码
- 新模块：在现有项目中新增目录和文件
- 代码修改：定位并修改现有文件

## 核心概念

- **Harness**：中央编排器，负责全局状态、流程控制、Agent 调度、上下文传递、异常处理
- **专业 Agent**：无状态执行者，每个 Agent 负责一个或多个阶段的具体工作
- **产物（Artifact）**：每个阶段的输出，结构化、不可变、版本化
- **质量门禁**：阶段产物进入下一阶段前必须通过的检查
- **回退**：下游发现上游产物问题时，回到上游修正后重新往下走
